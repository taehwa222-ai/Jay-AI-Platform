# 지원로그 문제 인터뷰 기록

> `interview-guide.md` 로 진행한 인터뷰 결과를 한 사람씩 여기에 남긴다.
> **통과 기준 4개 중 2개(인터뷰 완료 15명 · 구매 의향 5명)가 이 파일에서 나온다** —
> 나머지 2개(방문·사전예약)는 `npm run report` 로 읽는다.
>
> 개인 식별 정보는 **이메일 외에 수집하지 않고**, 여기에는 참여자 코드(P01…)만 쓴다.
> 이메일은 랜딩 D1 에만 두고 이 파일에 옮겨 적지 않는다.
> 검증이 끝나고 더 연락할 목적이 없으면 D1 의 이메일을 삭제한다.

## 집계 (일지에 옮겨 적을 숫자)

| 항목 | 목표 | 현재 | 판정 |
|---|---:|---:|---|
| 인터뷰 완료 | 15명 | 0 | 미달 |
| 제시 가격 구매 의향 ("예") | 5명 | 0 | 미달 |
| 최근 30일 6건 이상 지원 | 8명 | 0 | 미달 |
| 강한 문제 신호 | — | 0 | — |
| 반대 신호 | — | 0 | — |

> 인터뷰를 하나 마칠 때마다 이 표를 고치고, `daily-validation-log.md` 의
> "인터뷰 완료"·"구매 의향" 칸에 그날 증가분을 적는다.

## 판정 기준 (interview-guide.md 와 동일 — 다시 만들지 않는다)

| 판정 | 뜻 |
|---|---|
| **강한 문제** | 최근 30일 내 실제 사례 + 반복 빈도 + 현재 우회 해결이 있음 |
| **구매 의향** | 제시 가격에 명시적으로 "예" + 베타 연락 동의 |
| **약한 신호** | "좋아 보인다"지만 최근 사례·현재 해결 행동이 없음 |
| **반대 신호** | 기록 관리가 필요 없거나, 자동 제출 없이는 가치 없다고 답함 |

**"아마도"는 구매 의향이 아니다.** 예/아니오로 답하지 않으면 미확인으로 적는다.

## 기록 양식 (한 사람당 하나씩 복사해 쓴다)

```
### P00 — YYYY-MM-DD

- 유입 채널:
- 최근 30일 지원 건수 / 사용 포털:
- 가장 최근 겪은 실제 문제:
- 현재 해결 방법:
- 문제 발생 빈도 / 잃은 시간:
- 90초 데모 반응 — 먼저 쓰고 싶은 것 / 없어도 되는 것 / 못 믿겠는 것:
- 자동 제출 없는 경계에 대한 반응:
- 월 3,900원 구매 의향 (예/아니오):
- 30일권 vs 90일권 선호:
- 결제하지 않는다면 바뀌어야 할 조건:
- 반드시 필요한 기능 / 불필요한 기능:
- **판정**: 강한 문제 / 약한 신호 / 반대 신호
- **구매 의향**: 예 / 아니오 / 미확인
- 다음 인터뷰 소개 가능 여부:
```

## 중단·수정 판단 (experiment-plan.md 기준 — 인터뷰 10명 시점에 확인)

- [ ] 10명 중 **3명 미만**이 공고 삭제·서류 버전 혼선을 최근 경험 → **핵심 문제 재선정**
- [ ] 구매 의향은 높은데 사전예약 0명 → **가치 제안·신뢰 문구 먼저 수정**
- [ ] **절반 초과**가 자동 제출을 요구 → 안전한 제품 경계 안에서 대안 기능 재설계
- [ ] 포털 약관·기술 제한으로 공고 저장 불가 → URL·직접입력·이메일 전달로 범위 축소

하나라도 해당하면 남은 인터뷰를 계속하기 전에 멈추고 대표 판단을 받는다.
