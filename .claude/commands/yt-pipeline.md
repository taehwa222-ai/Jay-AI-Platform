`MY_COMPANY.md` 를 사규로 삼아 아래 순서로 진행한다. **각 단계는 별도 서브에이전트
(`yt-research` / `yt-planner` / `yt-qa` / `yt-writer` / `yt-production`)를 Agent 도구로 호출해서
수행한다** — 컨텍스트를 나눠 토큰을 아낀다.

## 순서

1. **시장조사** — `yt-research` 호출. 오늘 화제 이슈 후보 5개를 조사해
   `content/youtube/<날짜>-<슬러그>/research.md` 에 저장.
2. **기획** — `yt-planner` 호출. 1번 결과를 넘겨 아이디어 10개 → TOP3 산출,
   `ideas.md` 에 저장.
3. **검수** — `yt-qa` 호출. `ideas.md` 를 검사해 통과/반려 판정.
   - 반려된 안이 있으면 사유를 사용자에게 짧게 보고한다 (직접 고치지 않는다).
4. **★ 대표 승인 — 여기서 반드시 멈춘다.**
   검수 통과한 TOP3를 사용자에게 제시하고 **1개를 선택하도록 요청한다.**
   승인 없이 5번으로 넘어가지 않는다. 선택지: 승인 / 수정 요청 / 보류 / 폐기.
5. **대본** — 사용자가 승인한 안 1개만 `yt-writer` 에 전달해서 `script.md` 작성.
6. **컷 구성** — `yt-production` 호출. `script.md` 를 넘겨 `production.md` (컷·자막·촬영 메모)
   작성.
7. 마지막에 저장된 파일 경로 4개(research/ideas/script/production)를 한 줄씩 요약해서
   사용자에게 보고한다. 촬영·편집은 사용자가 직접 진행한다는 것을 다시 알린다.

## 규칙
- 4번(대표 승인) 전까지 대본을 미리 써두지 않는다.
- 검수가 2회 연속 전부 반려면 진행을 멈추고 사용자 판단을 요청한다 (반려 사유 목록 + 선택지:
  보완 후 재시도 / 이번 소재는 폐기).
- `MY_COMPANY.md` §2(브랜드 기준)가 비어 있으면 그 사실을 사용자에게 먼저 알린다 — 채워두면
  검수가 더 정확해진다고 안내하되, 채우지 않아도 진행은 계속한다.
