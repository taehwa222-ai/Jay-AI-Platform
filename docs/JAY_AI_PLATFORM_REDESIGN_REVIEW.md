# Jay AI Platform 개편 검토 보고서

> 검토일: 2026-08-15 · 기준 브랜치: `main` · 성격: 제품 방향과 다음 구현 단위를 위한 검토 문서

## 검토 범위와 방법

이 문서는 코드 변경 없이 현재 제품의 실제 흐름과 경계를 검토한 결과다. 코드와 로컬 브라우저 흐름을 1차 근거로 삼고, README·운영 문서는 의도와 운영 제약을 보완하는 자료로 사용했다. 실제 결제, OpenDART·OpenAI·시장 데이터 호출, VPS 배포, 운영 DB 접근은 수행하지 않았다.

검토 중 기존 미커밋 변경은 보존했다. 특히 이모티콘 콘텐츠 운영 화면을 추가하는 프론트엔드 작업은 진행 중 작업으로만 관찰했으며, 완성 기능으로 취급하지 않았다.

### 검토 결론

**Jay AI Platform의 회원용 핵심 제품은 “한국 개인 투자자가 종목을 기록·분석·검토용 리포트로 정리하는 워크벤치”로 좁히는 것이 타당하다.** 대표 개인의 YouTube·이모티콘 파이프라인은 같은 저장소에서 운영할 수 있지만, 회원 제품의 동등한 메뉴가 아닌 명시적 관리자 내부 도구로 분리해야 한다. 먼저 역할별 정보 구조와 미완성 콘텐츠 운영 연동을 정리한 뒤, 회원의 첫 분석 완료와 재방문을 측정하는 순서가 가장 작고 검증 가능한 다음 단계다.

### 작업 트리의 진행 중 변경

다음은 검토 시작 시 이미 존재한 변경이며 이 검토에서 수정하지 않았다.

- 수정됨: `backend/app/routers/content_ops.py`, `backend/app/schemas/content_ops.py`, `backend/app/services/content_ops.py`, `backend/tests/test_content_ops.py`, `backend/app/routers/platform.py`, `frontend/src/App.tsx`, `frontend/src/api.ts`, `frontend/src/components/ContentOpsScreen.test.tsx`, `frontend/src/components/ContentOpsScreen.tsx`, `frontend/src/types.ts`
- 미추적: `content/youtube/2026-08-13-trending-roundup/`, `content/youtube/2026-08-15-trending-roundup/`

변경은 콘텐츠 운영에 이모티콘 탭, 관리자 전용 API, 파일 기반 읽기 모델, 응답 계약, 접근 제어·경로 순회 회귀 테스트를 추가하고 플랫폼 모듈/로드맵에도 콘텐츠 운영을 표시한다. 시작 시점에는 프론트만 먼저 반영돼 404가 관찰됐지만, 검토 중 백엔드·테스트 변경이 추가된 뒤 새 격리 흐름과 관련 검사를 다시 확인했다. 이 통합은 아직 미커밋이므로 배포 완료로 취급하지 않는다.

## 대표 사용자 흐름

### 로컬 브라우저 관찰

관찰은 별도 임시 `DATA_DIR`를 쓰는 FastAPI와 Vite 서버로 수행했다. 기존 5173 개발 서버가 다른 API 대상을 쓸 수 있어, 최종 확인은 `127.0.0.1:8003` 백엔드와 명시적으로 연결한 `127.0.0.1:5175` 프론트에서 다시 했다. 테스트 가입 계정과 생성된 데이터는 임시 디렉터리에만 남겼으며 `backend/data/*.db`를 읽거나 바꾸지 않았다.

1. **비로그인 방문자**는 대시보드에서 `로그인`으로 진입해 이름·이메일·비밀번호로 가입할 수 있었다. 전역 메뉴에는 관리자·국내주식·콘텐츠 운영·수익화가 모두 보인다.
2. **첫 가입 관리자**는 가입 직후 관리자 화면으로 이동했다. 관리자 화면에는 회원·사용량·Pro 신청·리포트 현황이 함께 보였고, 국내주식 화면에서는 보유종목·관심종목·AI 분석·후보 스캔·Reports·Market·공시의 일곱 탭이 한 작업 공간에 표시됐다. 외부 시세·공시·AI·결제 호출은 하지 않았다.
3. **관리자 콘텐츠 운영**에서는 YouTube 프로젝트 목록, 단계 상태, 프로젝트의 읽기 전용 세부 문서가 표시됐다. 이 화면은 대표 전용이라는 제목을 직접 노출한다.
4. **일반 회원 콘텐츠 운영**에서는 프로젝트 목록이나 탭 대신 “관리자 계정으로 로그인하면 콘텐츠 운영 현황을 볼 수 있습니다.”라는 잠금 안내가 표시됐다.
5. **이모티콘 탭**은 시작 시점에는 `/api/v1/content-ops/emoticon` 404와 오류 원문/빈 상태가 함께 보였다. 이후 작업 트리에 추가된 백엔드·테스트 변경을 반영한 새 격리 흐름에서는 관리자에게 `gyeotgom`, 세트 2개, 캐릭터·조사·검수·서브캐릭터·성과 상태가 정상 표시됐다. 이 통합은 미커밋 변경이므로 릴리스 전 다시 확인해야 한다.

### 이 흐름이 말하는 제품 경계

- **검증된 사실:** 콘텐츠 운영은 서버와 UI 모두 관리자 인증을 요구한다. 회원용 주식 기능과 동일한 사이드바에서 접근 가능한 것은 정보 구조의 선택일 뿐, 권한상 같은 제품 기능은 아니다.
- **검증된 사실:** 일반 회원의 주식 워크벤치는 기능 밀도가 높고, 가입 후 바로 사용할 수 있는 핵심 작업 흐름을 이미 갖췄다.
- **추론:** 현재 전역 메뉴는 “모든 기능이 모든 사용자에게 같은 중요도”라는 인상을 준다. 회원의 첫 가치(종목을 추가하고 분석을 저장하는 일)보다 내부 운영·배포·수익화 아이디어가 먼저 보이므로, 제품의 약속과 작업 경로가 흐려진다.
- **추론:** 이모티콘 통합이 현재 작업 트리에서는 동작해도, 대표 내부 도구를 대시보드 주요 모듈로 홍보하면 회원 제품의 핵심 가치와 운영 도구의 릴리스 기준이 섞인다.

## 제품 경계와 정보 구조 문제

### 1. 두 제품 표면이 같은 내비게이션에 있다

현재 한 화면에 다음 두 표면이 동등하게 노출된다.

- 회원용: 계정, 한국 주식 분석/포트폴리오, 리포트 Market, Pro 전환
- 대표 전용: 콘텐츠 파이프라인 Markdown 열람, 제작 단계·성과 확인

루트 `AGENTS.md`는 개인 콘텐츠 파이프라인을 앱 회원 기능이 아니라고 명시한다. 이 원칙과 실제 권한 모델은 일치하지만, 전체 메뉴와 플랫폼 모듈 표시는 두 표면을 동등한 서비스 모듈처럼 보이게 한다.

### 2. “수익화”의 역할이 세 가지로 섞여 있다

현재 UI와 코드에는 다음이 함께 있다.

- 회원 플랜 전환과 결제라는 **제품 결제**
- 사용자가 만든 리포트를 발행하는 **콘텐츠/마켓 모델**
- B2B 공시 요약·교육을 소개하는 **사업 아이디어 목록**

이는 탐색 단계에서는 합리적이지만, 초기 사용자에게는 “무엇을 구매하거나, 어떤 결과를 얻는 서비스인지”를 불분명하게 만든다. 특히 리포트 발행은 현재 소유자가 직접 접근 수준을 바꾸는 모델이므로, 운영자 편집 리포트인지 사용자 생성 리포트 시장인지가 제품적으로 아직 결정되지 않았다.

### 3. 내부 운영 데이터의 노출·완성도 기준이 제품과 다르다

콘텐츠 운영은 로컬 파일을 읽는 관리자 도구로서 유용하다. 반면 회원 제품의 DB 모델, 권한, 데이터 품질 기대치와는 다른 수명주기와 품질 기준을 갖는다. 동일한 서비스 허브에 놓을 경우, 파이프라인 파일의 내부 작업 문서가 제품 기능처럼 보이거나 미완성 연동 오류가 일반 사용자 메뉴에서 드러날 수 있다.

### 4. 문서와 실제 모듈 지도가 조금씩 어긋난다

README의 화면 구조는 대시보드·로그인·관리자·매뉴얼·국내주식·수익화를 설명하지만 콘텐츠 운영은 포함하지 않는다. 반면 현 작업 트리의 플랫폼 API/대시보드는 콘텐츠 운영을 active 모듈과 로드맵 항목으로 추가한다. 기능을 추가할 때 제품 경계와 사용자 노출 정책을 같이 갱신하지 않으면, 코드·운영 문서·제품 메시지가 다시 어긋난다.

### 목표 사용자와 약속

- **주 사용자(권고):** 국내 상장 종목을 스스로 기록하고, 지표·리스크·공시를 한곳에서 검토하려는 개인 투자자.
- **제품 약속(권고):** “매수·매도 지시가 아닌, 내 종목과 관심 종목을 분석 근거·리스크·리포트로 정리하는 작업 공간.”
- **명시적 비약속:** 수익 보장, 개인별 매매 지시, 검증되지 않은 투자 성과.

```text
├─ 리포트 운영 정책/검수(필요 시)
└─ 대표 운영 도구
   └─ 콘텐츠 파이프라인 (YouTube/이모티콘; 회원 메뉴와 분리)
```

이 구조에서 콘텐츠 운영을 같은 배포물에 남겨도 된다. 단, 일반 회원의 기본 내비게이션·대시보드·공개 제품 소개에서 독립 제품 모듈로 홍보하지 않고, 관리자 영역의 `대표 운영 도구`로만 노출한다. 이모티콘 읽기 모델은 현재 작업 트리에서 권한 테스트와 격리 브라우저 흐름을 통과했으므로, 다음 변경에서는 회원 노출 정책과 운영용 릴리스 기준을 명시적으로 고정한다.

## 첫 구현 Goal과 측정 기준

### 먼저 필요한 대표 결정

다음 구현 전, 대표는 선택지 A를 기본 방향으로 승인하거나 B를 선택해야 한다. 이 판단은 가격·법률·배포가 아니라 제품의 주 사용자와 내부 도구 노출 정책을 정하는 사업 결정이다.

### 첫 구현 Goal: 회원 작업공간과 대표 운영 도구의 정보 구조 분리

**완료 조건 제안:**

1. 비로그인/회원/관리자 각각의 기본 메뉴와 첫 화면이 역할에 맞게 달라진다.
2. 일반 회원은 콘텐츠 운영·운영 매뉴얼·관리자 조작을 제품 탐색의 동등한 메뉴로 보지 않으며, 투자 작업공간과 계정·플랜에 바로 도달한다.
3. 관리자는 회원·플랜 운영과 대표 콘텐츠 운영을 한 운영 영역에서 명확히 구분해 접근한다.
4. 이모티콘 관리자 읽기 모델의 계약·브라우저 흐름을 유지하고, 회원 노출 여부를 역할별 정보 구조에 맞게 고정한다.
5. 회원의 `관심종목 저장 → 수동 분석 저장 → 분석 기록 재확인` 흐름을 브라우저에서 실제로 확인하고, 기존 인증·주식·관리자 권한 회귀 검사를 통과한다.

**후속 순서:**

1. 정보 구조/역할 노출 정리
2. 첫 분석 완료(activation) 흐름의 마찰 제거
3. 리포트 Market의 발행자·검수·접근 정책 결정과 구현
4. Pro 가치 가설과 결제 방식 검증

### 초기 측정 기준

운영 데이터가 생긴 뒤 다음을 사용자별·주간으로 관찰한다. 현재는 측정값이 없으므로 목표 수치는 대표가 초깃값을 정해야 한다.

- **Activation:** 가입 당일 관심종목 1개를 저장하고 분석 기록 1개를 남긴 신규 사용자 비율
- **반복 가치:** 7일 이내 분석 기록을 다시 열거나 새 분석을 저장한 사용자 비율
- **리포트 가치:** 분석 기록에서 리포트 초안을 만든 사용자 비율
- **전환:** free 사용자의 Pro 신청/결제 시도 및 승인·결제 완료 비율 (실패 사유 별도 기록)
- **내부 운영:** 콘텐츠 운영은 회원 전환 지표와 섞지 않고, 대표가 실제로 열람한 프로젝트 수·단계 누락 발견 수처럼 별도 운영 지표로 관리

## 리스크 · 미확인 사항 · 대표 결정 필요 사항

| 분류 | 항목 | 현재 상태 | 다음 행동 |

| 미확인 | 운영 환경 상태 | VPS 배포, 실제 사용자·결제 데이터, 외부 키 설정은 확인하지 않았다. | 운영자 승인 하에 민감정보 없이 상태 점검을 별도 진행한다. |

## 증거 목록

### 코드·문서

- 제품 규칙과 콘텐츠 파이프라인의 회원 기능 비범위: `AGENTS.md`
- 앱 라우팅/초기화: `backend/app/main.py`
- 인증·관리자·주식·결제·콘텐츠 운영 API: `backend/app/routers/auth.py`, `admin.py`, `stocks.py`, `payments.py`, `content_ops.py`
- SQLite 데이터·리포트 접근 규칙과 콘텐츠 파일 읽기: `backend/app/services/auth.py`, `stocks.py`, `content_ops.py`
- 콘텐츠 응답 계약: `backend/app/schemas/content_ops.py`
- 실제 화면/클라이언트 요청: `frontend/src/App.tsx`, `api.ts`, `components/AuthScreen.tsx`, `ContentOpsScreen.tsx`, `RevenueScreen.tsx`
- 운영 의도·배포 제약: `README.md`, `docs/DEPLOYMENT.md`, `docs/SERVER_OPERATIONS.md`
